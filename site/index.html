Agent evaluation harness · CI gate · v0.1.0

Did this change make the agent better or worse?

And can you reproduce the answer tomorrow? Meridian runs every trial in its own container, grades the state left behind from outside the sandbox, scores pass^k instead of a mean, and blocks a pull request only when a drop clears both a tolerance and a paired significance test. Then it tells you how small a regression it could have seen.

          § 03
          
    Why pass^3, not a mean
    
          
    pass^k = C(c,k) / C(n,k): the chance that k independent attempts all succeed. Never (c/n)^k. Below is the reference suite, run offline from committed cassettes.

          § 04
          
    The evaluator never trusts the container
    
          
    Assertions run on state extracted from the trial, on the host, after the container is gone. Nothing inside the sandbox decides whether the trial passed.
    
        
    

        

        
      
          
    • read_only=Truethe agent cannot install, patch or leave anything outside its mounts
      • 
          
    • cap_drop=["ALL"]an eval agent needs no capabilities, and each one kept is a way out
      • 
          
    • network_mode="none"or an internal network whose only other member is the proxy
      • 
          
    • memswap_limit = mem_limitno swap, so one task's memory ceiling cannot leak into its timeout
      • 
          
    • environment={MERIDIAN_WORKDIR}no key can be exfiltrated from a container that never received one
      • 
          
    • auto_remove=Falseremoval happens in a finally, after extraction, or a timeout becomes an empty result

          § 05
          
    An isolation claim that is allowed to fail
    
          
    One task writes a marker into /work. The next asserts it cannot see it. The probe must pass with isolation on, and it must fail with --unsafe-shared-env, or it proves nothing.
    
        
    

        
    

        
    
          
    
            
    And your assertions get the same treatment
    
            
    meridian suite audit runs every scored task against agents known not to have done the work. A task that still passes is measuring something weaker than it claims.

      Run it yourself
      
          
      Python 3.12+, uv and Docker. No API key: every run on this page talked to a deterministic stand-in provider behind the proxy.

$ make db        # postgres + migrations
$ make images    # build the environment snapshot, pin it by digest
